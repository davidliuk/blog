# Creational Patterns

创建型模式把对象的构造、配置和生命周期从使用方分离。使用它们的前提是“创建过程本身已经成为变化点”；普通构造函数足够时，不需要模式。

## Patterns

| Pattern | Use when | Main risk |
| --- | --- | --- |
| [Singleton](./singleton.md) | 进程内确实只需一个协调实例 | 隐藏全局状态、测试污染、并发初始化 |
| [Prototype](./prototype.md) | 从预配置对象复制比重新构造更自然 | 深浅拷贝、共享可变状态 |
| [Object Pool](./pool.md) | 资源创建昂贵且可安全复用 | 状态泄漏、容量阻塞、过早优化 |

## Design Test

1. 创建逻辑是否在多个调用方重复？
2. 生命周期由谁拥有，何时释放？
3. 对象是否可变，能否安全共享或复制？
4. 模式是否让依赖更显式、更容易测试？

模式应降低耦合，而不是隐藏配置、I/O 或全局状态。
