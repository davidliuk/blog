# System Design Resources

外部材料只有在进入自己的分析框架后才会形成能力。阅读一个架构案例时，不只记录“用了什么组件”，而要还原它面临的约束、演进顺序和失败经验。

## Reading Template

1. 系统服务谁，核心 workload 和规模是什么？
2. 最初瓶颈是什么，证据是什么？
3. 引入的新机制解决了哪一条约束？
4. 同时增加了哪些一致性、成本和运营复杂度？
5. 方案依赖哪些组织或基础设施前提？
6. 如果规模缩小十倍，哪些设计可以删除？

优先阅读官方 engineering post、论文和事故复盘；二手总结用于发现材料，不作为最终证据。
