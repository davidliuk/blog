# Big Table

这里把 Big Table 当成“宽表 / 列族存储”方向的设计入口，用来理解大规模 KV / 时序 / 稀疏数据的存储选择。

## 适合什么场景

- 数据量很大
- 行很多、列动态扩展
- 更强调按主键或范围读取
- 不追求复杂联表查询

## 常见特点

- 基于主键排序
- 更容易横向扩展
- 适合写多读多但查询模式相对固定的场景

## 什么时候考虑它

- 监控指标
- 用户行为日志
- Feed / Timeline 明细
- 稀疏列数据

## 和传统关系型数据库的区别

- SQL 更适合复杂关系与事务
- Big Table 风格更适合规模优先、模型更简单的数据访问
